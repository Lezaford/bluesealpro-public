# BlueSealPro

Field-service management for appliance repair shops. Track customers, schedule and dispatch jobs to
technicians, build invoices from a price book, and manage users and company settings from an admin area.

> **Portfolio project.** BlueSealPro is a retired app, published as a code sample. It is no longer deployed.
> All data in the demo is fictitious: names, emails (`example.com` / `example.org`), phone numbers (555-01xx)
> and addresses are generated by the seed script. The original customer data is not part of this repo.

## Features

- **Customers**: searchable, paginated list; up to four addresses per customer, phone and email, notes, tags,
  lifetime value; CSV import and export.
- **Jobs**: create jobs for a customer, assign a technician, track status and work performed.
- **Schedule**: a dispatch board showing jobs by day and technician, with rescheduling.
- **Invoices**: generated from a job, with line items drawn from the price book, tax and payments due.
- **Price book**: reusable services and parts with prices, taxable flag and lock policy.
- **Admin**: company settings and logo, user management with roles (owner, admin, tech, viewer).
- **Auth**: Devise sign-in, Pundit authorization, every record scoped to the signed-in user's company.
- **UI**: Tailwind with light and dark themes, keyboard-accessible menus and dialogs.

## Quick start

You need either [Docker](https://docs.docker.com/get-docker/) or [Podman](https://podman.io/) with Compose.
Nothing else: Ruby, Node and Postgres all run inside the containers.

```bash
git clone https://github.com/Lezaford/bluesealpro.git
cd bluesealpro
docker compose up --build        # or: podman compose up --build
```

The first start takes a few minutes. It installs gems, builds the CSS, creates and migrates the database,
and loads the demo data. It is ready when the logs stop scrolling and `docker compose ps` shows the `web`
service as healthy.

Then open **http://127.0.0.1:3100**.

Port 3100 is used instead of the Rails default 3000 so it does not clash with other local services.
To use a different port:

```bash
APP_PORT=3200 docker compose up
```

To stop it, press `Ctrl+C`, or run `docker compose down`.

## Logging in

1. Open http://127.0.0.1:3100 and choose **Log in** (or go straight to `/users/sign_in`).
2. Sign in with the demo account:

   | Email | Password |
   | --- | --- |
   | `admin@test.com` | `password` |

3. You land on the dashboard. A short "About this demo" notice appears on your first visit and explains that
   the data is fictitious. Reopen it any time from the footer link.

These credentials are public and for local use only. The seed refuses to run in production unless
`ALLOW_DEMO_SEED=1` is set. Never reuse this password anywhere real.

Public sign-up is disabled. The landing page has a "Request beta access" form that only stores a request.

## A quick tour

- **Dashboard** (`/dashboard`): an overview of upcoming and recent work.
- **Customers** (`/customers`): about 100 seeded customers. Try searching by name, company or phone, filtering
  by type, opening a customer, and exporting CSV.
- **Jobs** (`/jobs`): about 30 seeded jobs across the next and previous few weeks, with a mix of statuses.
- **Schedule** (`/schedule`): the dispatch board for the seeded technicians.
- **Invoices**: open a job and choose Create Invoice to add line items from the price book.
- **Admin** (`/admin`): company settings, users and the price book.
- **Theme**: use the sun/moon toggle in the header to switch between dark and light.

## Running without containers

You need Ruby 3.4.7 (see `.ruby-version`; [mise](https://mise.jdx.dev/) or rbenv work well), Node 18 or newer,
and a reachable PostgreSQL server. The easiest way to get Postgres is the compose service on its own:

```bash
docker compose up -d db          # Postgres on 127.0.0.1:5433
export DB_PORT=5433
```

Then:

```bash
bundle install
npm ci
bin/rails db:setup               # create, load schema, seed demo data
PORT=3100 bin/dev                # Rails server plus the Tailwind watcher
```

`config/database.yml` expects the user and password `blueseal` / `blueseal` in development and test, and
reads `DB_HOST` and `DB_PORT` if you need to point elsewhere.

## Configuration

| Variable | Default | Purpose |
| --- | --- | --- |
| `APP_PORT` | `3100` | Host port the app is published on (compose) |
| `DB_PORT` | `5433` | Host port for Postgres (compose, loopback only) |
| `DB_HOST` | `127.0.0.1` | Database host (`db` inside compose) |
| `FORCE_SSL` | `true` in production | Set `false` to run a production build over plain HTTP locally |
| `ALLOW_DEMO_SEED` | unset | Allow the demo seed to run in production |
| `DATABASE_URL`, `RAILS_MASTER_KEY` / `SECRET_KEY_BASE` | none | Production only |

See `.env.example` for the full list with placeholders. Never commit real secrets.

## Testing

```bash
docker compose exec web bin/rails test
```

On the host, run `bin/rails test`. The suite covers the customer model and search, plus an integration smoke
test that signs in and loads the main pages. CI (`.github/workflows/ci.yml`) also runs
Brakeman, bundler-audit and RuboCop.

## Useful commands

```bash
docker compose exec web bin/rails console      # Rails console
docker compose exec web bin/rails db:seed      # re-run the (idempotent) demo seed
docker compose exec web bin/rails db:reset     # wipe and re-seed
docker compose logs -f web                     # follow the app logs
docker compose down -v                         # stop and delete the database volume
```

## Project layout

```
app/
  controllers/     customers, jobs, invoices, schedule, technicians, admin/
  models/          Company, User, Customer, Job, Technician, Invoice, LineItem, PriceBookItem
  views/           ERB templates and shared partials
  javascript/      Stimulus controllers (menu, theme, demo notice, ...)
  assets/          Tailwind source and built CSS
db/
  migrate/         schema history
  seeds.rb         demo company, admin user, then seeds/demo_customers.rb
config/            routes, Devise, environment configs
test/              model, integration and smoke tests
```

Every record belongs to a `Company`, and controllers load data through `Current.company`, so one company
cannot see another's data.

## Troubleshooting

- **Port already in use.** Pick another with `APP_PORT=3200 docker compose up`.
- **Page does not load right after start.** The first boot builds everything; wait for the `web` service to
  report healthy (`docker compose ps`).
- **Login redirects back to the login page, or cookies are dropped.** If you run with `RAILS_ENV=production`
  over plain HTTP, set `FORCE_SSL=false`.
- **Styles look unstyled.** Rebuild the CSS: `docker compose exec web npm run build:css`.
- **Start over from scratch.** `docker compose down -v`, then `docker compose up --build`.
- **Podman on SELinux systems.** The compose file already mounts the source with the `:z` flag.

## Production notes

`Dockerfile` is the production image (built for Kamal or Fly.io). The Fly.io app this project used has been
deleted, so the deploy configuration is kept only as an example. Provide `DATABASE_URL` and
`RAILS_MASTER_KEY` (or `SECRET_KEY_BASE`); SSL is forced unless `FORCE_SSL=false`.
